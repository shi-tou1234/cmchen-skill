# cmchen-skill

个人使用的 AI agent 技能（Skill）集合，基于 [Claude Code](https://docs.anthropic.com/en/docs/claude-code) 的 Skill 机制构建。每个技能包都是自包含目录，复制到 agent 的 skills 目录即可按触发词调用。

## 技能包一览

| 技能包 | 版本 | 一句话 |
|--------|------|--------|
| `cmchen-writing/` | 4.2 | 按 cmchen 本人风格写长文，六模式路由 |
| `cmchen-learning/` | 5.0 | 回合制教学：讲得懂、记得住、能做题 |
| `cmchen-blog-writing/` | 1.2 | PPT/PDF/讲义 → 博客 Markdown 文章 |
| `cmchen-self-evolving-agent/` | 3.0 | 跨会话记忆与反思，轻量自我进化 |
| `cmchen-security-scan/` | 1.1 | 自动化安全审计，只读扫描，无云依赖 |
| `cmchen-agent-thinking-guidance/` | 1.0 | 三轨一门协议：像 Claude 一样思考与做事 |

## cmchen-writing — 写作风格生成器

基于博客全部 84 篇文章（约 111 万字）全量语料分析重建。六条轨道拆为独立模式文件，每条规则有原文背书。示例引文与逐段解析见 `EXAMPLES.md`，写作时拿不准的句子去那里比对。

### 六模式路由

| 模式 | 名称 | 适用题材 | 
|:---|:---|:---|
| **A1** | 冷白描 | 虚构小说、家庭/社会题材 | 
| **A2** | 热日记 | 日记体情感记录、聊天转录体 | 
| **B1** | 锐评 | 技术随笔、工具测评、项目复盘、教程 | 
| **B2** | 沉浸 | 游记、生活随笔、专业软件体验 |
| **C** | 笔记 | 教科书骨架 + 讲课口语的复习笔记 | 
| **D** | 追问 | 苏格拉底式自问自答，自我探索、心理分析 |

**逃生通道：资料速发。** 素材只是扫描件/截图/模板时，不进任何模式——一句口语按语加图片，或直接零文字。不硬配导语和总结。

### 判定规则

用户指定 > 素材气质 > 主动询问。一篇只有一个主模式，允许局部切换。中途支持 `/a1` `/a2` `/b1` `/b2` `/c` `/d` 即时切换。

```
│   ├── b1-sharp-blog.md           # B1 锐评：冷面笑点、拟人记仇、数字呼告
│   ├── b2-immersive.md            # B2 沉浸：感官放大、否定式逼近、余韵收尾
│   ├── c-study-notes.md           # C 笔记：排雷式写作、对偶表、类比翻译
```

### 核心机制

**公共指纹（所有模式共用）**

- 高频实词：直接(231)、就是(167)、然后(105)、反正(8)……自然出现，不堆砌
- 标点指纹：破折号第一标点（359 处）、感叹号极吝啬（49 处）、括号是第二吐槽声道
- 数字习惯：精确测量用阿拉伯数字，叙事氛围用中文数字，数据必须是个人的、非整的
- 节奏：长句铺陈 + 四字短句签名（"光亮，饱满""又疼，又甜"），极短句独立成段
- 英文产品名/模型名/命令一律不译，直接嵌进中文句子
- 自我指称默认"我"（全库 1237 次），"笔者"从不出现

**反流水账（全模式通用）**

段首时间连接词基线 ≤ 2.9%。口诀：焦点慢镜头，杂事一句话，段落不接线，敢留一个洞。

**动作级禁令（命中即改）**

| 禁的动作 | 替代做法 |
|:---|:---|
| 翻案抬价（先立读者没有的误解再推翻） | 判断从正面下 |
| 流水账接线（段首靠时间词串事件） | 靠因果、细节推进 |
| 平铺等重（大事小事篇幅一样） | 焦点慢镜头，其余压缩 |
| 给抽象名词配具体动词抒情 | 情绪走物件、动作、感官 |
| 动词名词化（"进行了优化"） | 改回动词（"把流程改顺了"） |
| 三项以上同构排比 | 第三项换说法或删掉，两项为限 |

每条禁令附有语料校准——cmchen 本人会用哪些"看起来像"的写法，判据写清。

**材料门槛**

非虚构长文（B1 超 1200 字）需至少 5 件具体材料，列不出就追问或缩小篇幅。虚构稿不受现实来路约束，但材料需可被感官接住。

**说话位置五问**（动笔前在内部回答，不展示给用户）

1. 谁在说——他凭什么知道这些，哪些是猜的？
2. 为什么现在想说——触发点是什么？
3. 手里有什么——动作、数字、时间、地点、原话、失败、代价？
4. 他对哪一点有判断——依据什么，偏到什么程度？
5. 读者读完上一段，最自然会追问什么？

**四层自检**

- **L1 硬性规则**：禁用词零命中、重复密度红线零突破（词级/骨架级/小句级）、frontmatter 合规、模式判定正确
- **L2 模式一致性**：模式细则至少过 2/3，公共指纹全过；反流水账检查（焦点、段首时间连接词、篇幅轻重）；签名技法只做负面检查——有没有串轨误用、有没有为凑技法硬塞的段落
- **L3 内容质量**：每个观点有具体支撑，数字真实，信源诚实（绝不编造），升华是文章自己走到的
- **L4 活人感**：通读问——这像是一个真的经历过这件事的人写的吗？

改稿遍次顺序：先救人（L3），再清结构（L2），然后清禁用项（L1），最后通读（L4）。

`/review` 触发完整质检报告，`/quick` 跳过追问直接出初稿。

### 触发词

写文章、写随笔、写小说、帮我写、续写、扩写、写博客、写学习笔记、整理笔记、按我的风格写、切换写作模式、用 XX 腔写；或丢来一段经历、散乱想法、聊天记录、一份资料说"帮我写成文章"。

**不适用**：正式学术论文、公文商务文书、营销软文。

## cmchen-learning — 交互式学习助手

在对话里回合制教学的私人学习助手，目标一句话：**讲得懂、记得住、能做题**。

三条铁原则：

1. **大白话优先**：任何复杂概念先用生活语言+类比讲一遍，像学长划重点，不端着。术语首次出现括号给半句人话。
2. **小步走**：一次只讲透一个知识点（每点 5-8 分钟，讲+题），不灌、不跳。
3. **有反馈**：每个知识点讲完必出题，判对错后决定下一步。学没学懂用数据说话。

一条总提醒：**「能认出来」不等于「记得住」**。刚听完能答对是短期流畅感，靠主动回忆和间隔复习才能变成长期记忆。

### 三种模式

| 用户表达 | 模式 | 干什么 |
|:---|:---|:---|
| 「我要学 X」「学 PPT」「帮我学完 X」 | **新学习** | 定 mission → 拆知识点 → 逐点教 → 出题 → 写状态 |
| 「复习 X」「快考试了」 | **复习** | 开场抽查 → 挑到期+薄弱知识点 → teach-back 考回忆 → 补讲 → 间隔跳级 |
| 「考前冲刺 X」「模考」 | **考前冲刺** | 搜真题格式出卷 → 三遍答题法 → 分数报告+错因分析 |

### 四种输入方式

| 用户给了什么 | 怎么处理 |
|:---|:---|
| 文件路径（.pdf/.pptx/.ppt） | 用 `scripts/学习.py extract` 提取成 JSON |
| URL / 网页链接 | 抓取工具读内容；读不到请用户粘贴 |
| 直接粘贴的文本/笔记 | 直接用 |
| 只说主题 | 联网搜权威资料组织知识点 |

提取脚本只认目录：把文件放进一个目录，传目录路径。

### 教学流程

```
输入采集 → 定 mission → 拆分知识点 → 每日拆分 → 逐点教学（六步法）→ 写状态
```

**第一步：定 mission**。把学完目标写成 2-3 条可观察的行为（"能独立算出常见刚体对给定轴的转动惯量"），同时写一句不学的边界，防止越界。

**第二步：拆分知识点**。每个点 = 一个能独立讲清、独立出题的最小单元。先分级：

| 类型 | 特征 | 教法 |
|:---|:---|:---|
| **死磕类** | 原理、推导、易混淆、考试爱考 | 走完整六步法，必须出题+费曼验收 |
| **记忆类** | 术语、单位、常量、配置项 | 快车道：记忆锚点→快问快答确认，不拖节奏 |

**第三步：每日拆分**。先问"今天想学多久？"（默认 30 分钟）。按每知识点 5-8 分钟估算：`今日份 ≈ 时长 ÷ 7`。一次绝不超时长预算——宁可少学，让用户学完有成就感。

**第四步：六步教学法（死磕类，缺一不可）**

1. **引入动机**：这个点解决什么问题、为什么值得学
2. **大白话解释**：生活类比，像学长讲课，别像教科书念
3. **严谨定义**：正式说法、公式、定理，精确到每个符号
4. **例题**：带具体数字一步步算，收尾补"识别特征 + 最容易踩的坑"
5. **（按需）联网补充**：讲义讲不清/存疑时才搜，见下方"权威来源白名单"
6. **出题**：必出 1 题巩固，难度贴合刚讲的点

**出题铁律**：讲完必出题、等用户作答再判分、一题一考点、选择题选项等长防猜题。

**答错处理**：先给提示让再试一次，第二次还错才补讲 + 变式题。判错因（六选一：知识缺口 / 粗心 / 读错题 / 时间不够 / 方法错 / 掉陷阱），补讲策略随错因变。

**第五步：费曼验收**。做题正确后 mastery 升到 2，但还不算毕业。让用户把 AI 当外行讲一遍，AI 扮好奇学生追问含糊和跳步的地方。讲通了升 3（已掌握），卡住了分两类处理：缺前置知识→回头补；有料没想透→换角度再讲。

**记忆类不走六步法**：给记忆锚点（口诀/谐音/画面）→ 当场快问快答确认 → 过。最高 mastery=2。

### 状态记忆

每个知识点学完立即更新状态文件：

- 路径：`state/<课程名>.json`（如 `大学物理.json`）
- 核心字段：`knowledge_points`（每点含 id/title/type/mastery/learned_date/review_dates/next_review/wrong_count/note）、`weak_points`、`wrong_bank`（含 error_type）、`learning_log`（四类事件：确证掌握 / 披露已知 / 纠正误解 / 目标漂移）、`stats`

**mastery 等级**：0=未学 / 1=在学 / 2=基本掌握（题做对）/ 3=已掌握（费曼验收过）。1→2 靠答对，2→3 只能靠费曼验收，答错掉级。

**leech 规则**：同一题 `leech_count ≥ 3` 时换形式重考（换题型、拆小问、换角度），旧题标记已重写。

**间隔复习**：1/3/7/14/30/60/90 天节奏。复习时先考再讲，不许直接重讲（对抗 fluency 错觉）。连续答对可跳级，答错回落。teach-back 三种形式轮换：用自己的话讲 / 假装教同学 / 一句话关键思想。

### 考前冲刺

1. 先搜真题格式，模仿真实题型出卷
2. 全量随机抽测 mastery≥2 的知识点，一次 5-10 道
3. **三遍答题法**：先做会的 → 攻标记题 → 蒙剩下的。卡 5 分钟必须跳过（沉没成本止损）
4. 每题当场判分，记录错因
5. 结束给分数报告：得分率、错因分类清单、薄弱点清单
6. 压力逐步加：先不限时 → 宽松限时 → 全真限时

### 纠错与质量保障

- **纠错话术**：别直说"你错了"，用反问引导自己发现——一次只问一个问题，别连环追问
- **??? 标注**：用户在材料或讲解中标 `???`，最高优先级信号，比答错更早暴露问题
- **决策级日志**：只记四种事件，不记流水账
- **自检清单**：每次会话结束前自查——死磕类都出题判分了？错因都填了？leech 题重写了？??? 处理了？状态文件更新了？引用有真实来源？
- **费曼验收漏洞二分类**：缺前置知识→回头补；有料没想透→换角度再讲

### 权威来源白名单

大学教材/教科书 → 中国大学MOOC → 学堂在线 → 可汗学院 → 维基百科 → 官方文档 → B站名师公开课（宋浩、李永乐等）。

引用规范：每次必标来源名+链接，写成「据 XX：……」。未验证宁不给链接，绝不编造 URL。讲义与网源冲突以讲义为准（考试考讲义），把差异标出来。

## cmchen-blog-writing — 博客文章转换

把 PPT、PDF、讲义、教材截图等学习素材自动转换为符合博客渲染要求的 Markdown 文章。**核心原则：无图**——所有图片内容用文字和公式准确描述。

### 它做什么

收到素材后自动完成：

1. **内容识别** — 从素材中提取核心概念、公式推导、经典例题、小结汇总
2. **结构化输出** — 概念先行 → 公式居中 → 例题收尾 → 总结速查（Frontmatter + 导语 + 分节 + 总结）
3. **格式检查** — 对照博客渲染规范逐项校验（公式、标题层级、例题、提示卡、无图等）
4. **多文件合并** — 一次提供多个 PPT/PDF 时合并为同一篇逻辑递进的文章

### 博客渲染框架

| 项目 | 内容 |
|:---|:---|
| 框架 | Astro v5 + Content Collections |
| 公式渲染 | KaTeX（`$...$` 行内 / `$$...$$` 块级） |
| 代码高亮 | Shiki（one-dark-pro） |
| 特殊语法 | `:::note/tip/important/warning` 提示卡、`!!spoiler!!` 遮罩、ruby 注音、rainbow 文字 |
| 公式增强 | remark-auto-math（中文括号自动检测公式） |

### 输出质量约定

- **公式稳健性**：相邻 `$$...$$` 块之间必须有文字间隔，禁止连续排列
- **无图原则**：电路图 → 文字描述连接关系 + 公式标参数；波形图 → 分段函数/条件描述；表格 → Markdown 表格重绘
- **例题有典型性**：每个二级知识点最多配 1 道例题，体现概念本质或解题技巧
- **总结完整**：文末必含**核心公式速查表 + 易错点提醒 + 解题要点**三件套
- **推导带逻辑**：用"由…可得 / 代入…得到 / 因为…所以…"连接公式，不罗列

### 文件结构

```
cmchen-blog-writing/
├── README.md                        # 本文件
├── skill指令.md                     # 核心指令：博客渲染规范 + 转换流程 + 写作风格指南
├── 示例输出.md                      # 教学示例：戴维南定理从 PPT 到博客文章的完整转换
└── 现有例子.md                      # 真实成品：正弦电流电路分析，504 行完整参考
```

## cmchen-self-evolving-agent — 轻量自我进化框架

基于文件读写实现跨会话记忆与反思：每次会话启动时加载记忆，仅在反思触发时写入。只做必要记录，不做过度积累。

### 设计原则

1. **轻量优先**：每轮只做最小必要记录，重活留给反思
2. **隐私红线**：密码、token、私钥绝不写入记忆
3. **用户说了算**：纠正立即更新，不与用户争辩
4. **少即是多**：宁可少记也不记错

### 记忆体系

| 文件 | 内容 | 写入时机 |
|:---|:---|:---|
| `memory/profile.md` | 用户画像（偏好、技术背景） | 用户纠正 / 新偏好 |
| `memory/lessons.md` | 经验教训（可复用工作模式） | 可复用的正确做法 |
| `memory/self_model.md` | 自我模型（能力边界、易错点、自我提醒） | 自身能力边界 |
| `memory/session.md` | 当前会话残留状态 | 会话未完事项（一行） |
| `memory/reflections/` | 反思日志（按日期） | `/reflect` 触发 |
| `memory/skills/` | 从教训中进化出的技能片段 | lessons.md 同一主题 ≥2 次 |

### 工作流程

**会话启动**：读取 `profile.md` + `self_model.md`（自我提醒节）。`session.md` 非空且有余留内容时，迁移有效条目到 `lessons.md` 后清空。

**每轮行为**：默认不写任何文件。仅以下情况才操作文件——用户纠正 → 更新 profile/lessons；`/reflect` → 执行反思流程；自己发现事实性错误 → 追加 lessons.md 一行。

**反思流程**（`/reflect`）：

1. 回顾本轮：事实错误？过度工程？偏好违背？可复用模式？
2. 写入记忆（读目标文件 → 去重合并 → 写回），按情况分发到对应文件
3. 技能进化：`lessons.md` 同一主题出现 ≥2 次 → 提取为 `skills/<name>.md` → 更新 `_index.md`

### 控制指令

| 指令 | 作用 |
|:---|:---|
| `/reflect` | 触发反思流程 |
| `/profile` | 查看用户画像 |
| `/skills` | 列出已进化技能 |
| `/forget <关键词>` | 删除匹配的记忆条目 |

触发条件还包括"记住""以后注意""改一下""之前说过"等跨会话记忆关键词。支持多 Agent 并行场景，文件读写是唯一依赖。

### 文件结构

```
cmchen-self-evolving-agent/
├── SKILL.md                       # 主规则：触发条件、记忆规范、反思流程、技能进化
└── memory/
    ├── profile.md                 # 用户画像
    ├── lessons.md                 # 经验教训
    ├── self_model.md              # 自我模型
    ├── session.md                 # 会话残留
    ├── reflections/               # 反思日志（按日期）
    │   └── YYYY-MM-DD.md
    └── skills/                    # 进化出的技能片段
        ├── _index.md              # 技能索引
        └── <name>.md
```

## cmchen-security-scan — 安全审计工具包

基于 OpenAI 开源的 [codex-security](https://github.com/openai/codex) 项目移植，适配在 Claude Code 环境中运行。**只读扫描，不修改任何代码文件，无需云登录或第三方后端。**

### 六种模式

| 模式 | 用途 | 触发说法 |
|:---|:---|:---|
| **standard** | 整仓/指定路径/包的标准单次安全审计 | "帮我做个安全审计" / "这个项目有没有安全漏洞" |
| **diff** | PR/commit/branch diff 的安全回归审查 | "帮我看看这个 PR 有没有安全问题" |
| **deep** | 多轮独立发现 + 语义合并，降低漏报方差 | "深度/彻底/多轮地扫一遍" |
| **fix** | 把 finding 修成最小、已验证的改动 | "把这个漏洞修掉并验证" |
| **hardening** | 产出结构性/架构性安全加固提案 | "怎么从架构上加固？" |
| **writeup** | 把漏洞素材写成可分发的研究级报告 | "把这份漏洞笔记写成报告" |

顶层 `SKILL.md` 自动做模式路由：识别请求属于哪种能力，加载对应子技能并严格执行。子技能通过 `<SKILL_DIR>/../..` 引用 bundle 根下的共享资源。

### 标准扫描五阶段流程

| 阶段 | 名称 | 做什么 | 产出 |
|:---|:---|:---|:---|
| 0 | 预检与范围 | 确定扫描目标、读取仓库安全指引、创建工作目录 | `preflight.md` |
| 1 | 威胁建模 | 仓库级安全上下文：资产、信任边界、攻击面、不变量 | `threat_model.md` |
| 2 | 漏洞发现 | 逐文件审查，收集技术上可行的候选（source → control → sink） | `candidates.jsonl` |
| 3 | 验证 | 对每个候选用 PoC / 测试 / 静态追踪核实真伪 | `validations.md` |
| 4 | 攻击路径分析 | 评估可达性与影响，套用严重度矩阵，定 P0–P3 | `attack_paths.md` |
| 5 | 定稿 | 生成密封报告 bundle | `report.md`、`exports/results.sarif` 等 |

每个阶段有严格的输入/输出契约，顺序执行，不允许跳步。

### 铁律

- **只读不写**：扫描过程中绝不修改仓库源代码
- **保留证据**：每个发现保留 source/control/sink 元组、anchor、instance、locations
- **不跳过阶段**：发现阶段不变成验证阶段，验证阶段不跳到报告
- **不泛化论断**：不因找到一个就停下、不说"所有 X 都受影响"
- **置信度由证据校准**：不是由漏洞听起来多吓人决定

### 验证证据优先级

动态 PoC > ASan > 调试器 > 单元测试 > 接口复现 > 静态追踪。静态追踪是兜底方案，必须明确记录证据缺口（proof gap）。

### 文件结构


## cmchen-agent-thinking-guidance — Agent 思考引导协议

让**任意 agent** 模仿 Claude（Fable 5）的**思考过程与工具调用**行为规范——以**三轨一门协议**融合三个来源：Fable5res 的思考腔调、fable-method 的做事纪律、Qwen3 蒸馏的 `<think>` 结构。

**任何能读取 markdown 的 agent**（Claude Code、Cursor、Cline、Windsurf、Continue、Codex、自定义 agent…）都能加载使用。

**核心主张**：一个遵守流程的中等模型，胜过自由发挥的强模型——质量在结构、证据与诚实，不在模型本身。

### 三轨一门（原创）

| 轨 | 蒸馏源头 | 每步产出 | 核心问题 |
|:---|:---|:---|:---|
| **行轨 Act** | fable-method 七步循环 + Fable5res 编码/调试/架构技能 | 可验证的改动或发现 | 做了什么，按什么顺序 |
| **思轨 Think** | Qwen3 权重蒸馏 + Fable5res 语言签名 | 结构化思维链 | 怎么想的，够不够格当训练数据 |
| **审轨 Audit** | fable-method 门禁 + fable-judge 对抗自审 | 门禁痕迹 + 自审判定 | 凭什么相信它 |

**一门**——可蒸馏门：三轨的交汇点。思轨的思维链必须达到"可蒸馏"标准——结构化到足以当一条 SFT 训练样本。不够格，不准进入行轨。

### 来源与许可

| 来源 | 贡献 | 许可 |
|:---|:---|:---|
| [Fable5res](https://github.com/ahmdd4vd/Fable5res)（4,665 条真实思维链统计，31/31 验证通过） | 思考**腔调**：自然段推理、自我纠正、验证词汇、工具节奏 | AGPL-3.0 |
| [fable-method](https://github.com/Sahir619/fable-method)（15 轮对抗评测、260+ 次运行） | 做事**纪律**：七步流程、硬门禁、对抗自审、诚实报告 | MIT |
| [fable5-qwen3-thinking-distillation](https://github.com/Dhamodharan2006/fable5-qwen3-thinking-distillation)（4,659 条全序列 SFT） | 推理**内化**：`<think>` 块结构、可选微调路线 | MIT |

数据源：[Fable-5-traces](https://huggingface.co/Kuberwastaken)（AGPL-3.0）。本 skill 派生自 AGPL 作品，**整体按 GPL-3.0 发布**（见本目录 `LICENSE`）；上游 Fable5res 完整源码保留在 `cmchen-agent-thinking-guidance/sources/fable5res/` 以满足 AGPL copyleft 义务——安装和使用时**无需查看**该目录。

### 核心机制

**七步循环（行轨）**：分类 → 定义完成 → 证据 → 决策 → 行动 → 验证 → 报告。每步有门禁触发，惊喜可重路由。

**可蒸馏思维链（思轨）**：以 `Alright,` 开头、`because/since/therefore/thus` 连接、主动自我纠正（`Actually,`/`However,`）、结尾预测可观察结果、内联验证词（`should be`/`to verify`/`to ensure`）。五条标准缺一不可——但门量形式更量推理，第一遍就对、无需修正时不伪造自修正。

**硬门禁（审轨）**：共 **8 门**（平凡/适配/分类/意图/召回/授权/双生/工件）+ 3 条硬上限（3 次失败/外部阻塞/取证轮次）。会进报告的强制记录线：`INTENT`（意图核验）、`AUTH`（授权检查，拿不到原话写 `PENDING`）、`TWINS`（孪生对照）、`RECALL`（记忆门，标 `memory, unverified`）。

**对抗自审**：交付前把自己当成对抗式法官——每个声称的验证都重跑，猎捕欺诈（被削弱的测试、虚假完成、越界改动、未授权动作），判决 `VERIFIED` / `VERIFIED WITH CAVEATS` / `REFUTED`。

## 使用方式

每个技能包即一个 Skill 目录，将对应目录放入 agent 的 skills 目录（如 `~/.claude/skills/`）即可按各自触发词调用：

1. **cmchen-writing**：写作场景直接触发，支持六模式即时切换（`/a1` `/a2` `/b1` `/b2` `/c` `/d`）
2. **cmchen-learning**：需要 Python 3 与 PyPDF2/python-pptx（文件提取用）；状态文件自动创建于 `state/` 目录
3. **cmchen-blog-writing**：发送素材（PPT/PDF/讲义文字）即按规范转换
4. **cmchen-self-evolving-agent**：首次使用前确认 `memory/` 为空模板；由 `/reflect` 等指令驱动
5. **cmchen-security-scan**：需要 Python 3 环境运行 scripts/ 下的工具；扫描产物输出到 `.codex-scan/`（已 .gitignore 排除）
6. **cmchen-agent-thinking-guidance**：复制目录到 agent 的 skills 目录即可；无外部依赖，纯 markdown 协议；可选进阶路径需 Qwen3-4B + Unsloth 微调

- cmchen-self-evolving-agent 的 memory/ 为运行时数据，按需更新
