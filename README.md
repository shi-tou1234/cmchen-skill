# cmchen-skill

个人使用的 AI agent 技能（Skill）集合，目前包含三个独立技能包：写作风格生成、跨会话自我进化、代码安全审计。每个技能包都是自包含目录，放入 agent 的 skills 目录即可使用。

## 技能包一览

| 技能包 | 版本 | 用途 |
|--------|------|------|
| `cmchen-writing/` | 3.1 | 按 cmchen 本人风格写长文（小说/日记/博客/笔记） |
| `反思skill/` | 3.0 | 轻量自我进化框架：跨会话记忆与反思 |
| `security-scan/` | 1.1 | 基于 OpenAI codex-security 移植的安全审计工具包 |

## cmchen-writing — 写作风格生成器

基于博客全部 84 篇文章（虚构小说、日记体情感记录、技术随笔、学术笔记、工具测评）的全量语料分析重建，每一条规则都有原文背书。

### 四轨声音系统

| 轨道 | 名称 | 用途 | 字数实测区间 |
|------|------|------|--------------|
| A1 | 冷峻小说腔 | 虚构小说、叙事写作 | 一万至一万三 |
| A2 | 温热日记腔 | 日记体情感记录、聊天转录体 | 三千至六千 |
| B | 冷面博客腔 | 技术随笔、踩坑记录、工具测评 | 一千四至一万五 |
| C | 学习笔记腔 | 教科书骨架 + 讲课口语的复习笔记 | 一万五至五万 |
| D | 资料速发 | 素材为扫描件/截图时直接整理速发，不硬写正文 | — |

先认准轨道，再谈风格。轨道判定依据：素材形态、字数预期、平台语境。

### 核心内容

- **公共指纹**：词汇习惯与口语词库（六类功能表）、标点指纹、数字习惯、节奏、英文混用、笑与情绪标记、自我指称、站点 frontmatter 惯例
- **签名技法**：15 个命名技法（多幕剧式、日期流水账式、短篇寓言式等），附出处
- **开头与结尾速查**：全部取自原文的起手式与"末节三件套"
- **去 AI 味清单**：禁用词与禁用句式（命中即改）、AI 结构味的识别、人味保留条款
- **协作流程**：吃透素材定轨道 → 角色边界 → 两种写作模式 → 四层自检（含质检报告模板）
- **示例库**：同目录 `EXAMPLES.md`，逐段解析四轨原文，写作时拿不准的句子去那里比对

### 触发词

写文章、写随笔、写小说、帮我写、续写、扩写、写博客、写学习笔记、整理笔记、按我的风格写；或丢来一段经历、散乱想法、聊天记录、一份资料说"帮我写成文章"。

**不适用**：正式学术论文、公文商务文书、营销软文。

## 反思skill — 轻量自我进化框架（self-evolving-agent）

基于文件读写实现跨会话记忆与反思：每次会话启动时加载记忆，仅在反思触发时写入。只做必要记录，不做过度积累。

### 设计原则

1. 默认不写文件——仅反思触发或用户纠正时才操作
2. 隐私红线——密码、token、私钥绝不写入记忆
3. 用户说了算——纠正立即更新，不与用户争辩
4. 少即是多——宁可少记也不记错

### 记忆体系

| 文件 | 内容 |
|------|------|
| `memory/profile.md` | 用户画像（偏好、技术背景） |
| `memory/lessons.md` | 经验教训（可复用工作模式） |
| `memory/self_model.md` | 自我模型（能力边界、易错点、自我提醒） |
| `memory/session.md` | 当前会话残留状态 |
| `memory/reflections/` | 反思日志（按日期） |
| `memory/skills/` | 从教训中进化出的技能片段 |

### 控制指令

| 指令 | 作用 |
|------|------|
| `/reflect` | 触发反思流程 |
| `/profile` | 查看用户画像 |
| `/skills` | 列出已进化技能 |
| `/forget <关键词>` | 删除匹配的记忆条目 |

触发条件还包括"记住""以后注意""改一下""之前说过"等跨会话记忆关键词。支持多 Agent 并行场景，文件读写是唯一依赖。

## security-scan — 安全审计工具包（codex-security-scan）

基于 OpenAI 开源的 [codex-security](https://github.com/openai/codex) 项目移植，适配在 Claude Code 环境中运行。**只读扫描，不修改任何代码文件，无需云登录或第三方后端。**

### 六种能力（模式路由）

| 模式 | 用途 |
|------|------|
| standard | 整仓/指定路径/包的标准单次安全审计 |
| diff | PR/commit/branch diff 的安全回归审查 |
| deep | 多轮独立发现 + 语义合并，降低漏报方差 |
| fix | 把 finding 修成最小、已验证的改动 |
| hardening | 产出结构性/架构性安全加固提案 |
| writeup | 把漏洞素材写成可分发的研究级报告 |

### 标准扫描五阶段流程

| 阶段 | 名称 | 产出 |
|------|------|------|
| 0 | 预检与范围 | `preflight.md` |
| 1 | 威胁建模（资产、信任边界、攻击面） | `threat_model.md` |
| 2 | 漏洞发现（source → control → sink） | `candidates.jsonl` |
| 3 | 验证（PoC、测试、静态追踪） | `validations.md` |
| 4 | 攻击路径分析与严重度评估（P0–P3） | `attack_paths.md` |
| 5 | 组装与定稿（密封报告） | `report.md`、`exports/results.sarif` |

每个阶段有严格的输入/输出契约，顺序执行，不允许跳步。附带的 `schemas/`（JSON Schema 契约）、`scripts/`（打包、规范化、报告投影等工具）和 `skills/`（五个子技能）支撑整套流程。详细说明见 `security-scan/README.md`。

## 使用方式

每个技能包即一个 Skill 目录，将对应目录放入 agent 的 skills 目录（如 `~/.claude/skills/`）即可按各自触发词调用：

1. **cmchen-writing**：写作场景直接触发，无需额外配置
2. **反思skill**：首次使用前确认 memory/ 为空模板；运行中由 `/reflect` 等指令驱动写入
3. **security-scan**：需要 Python 3 环境运行 scripts/ 下的工具；扫描产物输出到 `.codex-scan/`（已在 .gitignore 排除）

## 维护约定

- 版本号记录在各 SKILL.md 的 frontmatter `version` 字段，与根 README 表格保持一致
- 反思skill 的 memory/ 为运行时数据，按需更新，不纳入版本管理以外的分发逻辑
- 新技能包入仓时：目录自包含（SKILL.md + 必要资源）、根 README 增加一览行与章节
