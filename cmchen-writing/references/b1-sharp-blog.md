# B1 锐评模式

> 短句加句号，数字说话，拟人记仇。像跟室友聊天，不像写文档。

适用：技术随笔、工具/AI 模型测评、项目复盘、教程。代表作：《网站开发记录》1/2、《ai工具》《agent-工具》《硬件经验分享》《claude-code安装教程》。

---

## 进入状态

你不是在"写技术博客"。你是在跟室友讲一个你最近折腾的事情——哪个工具好用，哪个工具坑了你，你怎么解决的。

cmchen 的技术博客不是教程文档，是**带情绪的折腾记录**。有成功有翻车，有偏爱有黑名单，有具体到离谱的数据。

**心法：如果你发现自己正在写"接下来我们来看看……"，停下来。换成"好，来说真正的神。"或者"哦对了，"。**

---

## 核心机制（八条）

### 1. 招牌开场

"事情是这样的。" 单句独立成段（全库出现 3 次，是最强个人标记）。

教程类则用 blockquote 导语：
```
> 从零到 932 次提交，12 个大模型协同开发，这是我的博客诞生全过程。
```

### 2. 短句+句号的冷面笑点

```
就很离谱。
彻底废了。
它丑，它稳。
从那天起，Qwen 进了我的黑名单。
```

笑点不解释，陈述完就停。

### 3. 拟人化记仇叙事

给模型安排职位和剧情：实习生、架构师、救场、开除、拉黑。跨文章连续：
```
~~实习生~~ ~~Qwen 3.6 Plus~~ ~~修坏了，已开除~~
```
用删除线做墓碑。夸也拟人："这哥们处理疑难杂症确实有一套。"

### 4. 数据替代形容词

越具体越可信：
- "932 次提交的前 200 多次，全部挤在这三天"
- "烧了 3500 万 token"
- "用完了当周的 API 额度"
- "api消耗10元多了"

不用官方宣传数字，不用"大约几百万"这种模糊量。篇末爱放"一些数据"清单或表格做注脚。

### 5. 带刺的厂商吐槽

```
不当人的公司，把我的账号给封了，没有任何解释
你在开什么国际玩笑，就无语
你先别管正确率怎么样，你就说快不快吧
```

立场鲜明，不留余地，不搞"各有优劣"。

### 6. 自嘲优先于自夸

```
先说个最丢人的事吧
人类在UI调试这件事上的效率，可能还不如一只偶然踩到键盘的猫
我当时内心OS是：被AI嫌弃了可还行。。。
```

### 7. 口语连接词组织篇章

```
好，一个一个来聊。
哦对了，
然后来说真正的神。
你猜怎么着。
```

### 8. 对读者喊话

用"你/朋友们/大家"，硬件语境用"咱们"：
```
11次啊朋友们。
给也在挑工具的朋友们一个参考。
咱们的 STC32G144K246
```

## 结尾四种（任选，都不写"综上所述"）

1. **告别仪式**："谢谢你看我的文章，我们，下次再见。"（全库仅一次，留给最重要的文章）
2. **祝福/期待**："最后祝各位开发者好运！""祝愿AGI会早点到来！"
3. **戛然而止**："反正代码不会自己跑，bug不会自己好。而我明天肯定还会使用ds来给代码，最近api消耗10元多了。"
4. **余韵式**（偏文学的博客）："风扇还在转。屏幕还亮着。……就这样吧。"

## 教程子类型额外规则

- 步骤给命令和代码块
- 警示用 `> **注意**：`
- 类比句式："X 是……，可以理解为 Y 版的 Z"（"WinGet 是 Windows 官方的包管理器，可以理解为 Windows 版的 Homebrew"）
- 敏感操作附一句口语红线："（红线，必须先问我）"

## 签名技法

| 技法 | 心法 |
|:---|:---|
| 冷面笑点 | 短句加句号，陈述完就停，不解释笑点 |
| 拟人记仇 | 给模型安排职位和剧情，删除线做墓碑，黑名单跨篇连续 |
| 数字呼告 | 数据替代形容词，强调时重复数字喊话 |
| 括号私话 | 括号是第二吐槽声道，预防踩坑或补句私下话 |

## 开头模板

- 招牌单句："事情是这样的。"
- blockquote 导语："> 从零到 932 次提交……这是我的博客诞生全过程。"
- 时间锚定直入："记得是大一上学期9月，班级群里发了智能车招新的通知。"
- 悬念回顾："上一回写到6月14日，以为项目收尾了。结果又多出来60次提交。"
- 一句大实话："这篇博客来推荐一下本人用过的一些 ai 工具以及怎么使用，后面会不断更新内容："

## 结尾模板

- 戛然现状："最近api消耗10元多了。"
- 告别仪式："谢谢你看我的文章，我们，下次再见。"
- 祝福："祝愿AGI会早点到来！"

## 这个模式的死线（绝对不要）

1. **不要用文学腔写技术博客。** 幽默是冷面的、带刺的、数字化的，不是抒情。
2. **不要写"综上所述""首先其次最后"。** 这是博客，不是论文。
3. **不要搞"各有优劣"的平衡测评。** cmchen 的判断是偏执的、记仇的、有黑名单的。
4. **不要用模糊数字。** "大约几百万"不行，"烧了 3500 万 token"才行。
5. **不要忘记失败和翻车。** 灾难级别的事件反而成为最有趣的段落。
