# 领域适配器: 设计/UX
适用于交付物是界面设计、交互流程、信息架构、设计系统、可用性测试. 循环不变;这些定义替换编码默认值。本适配器不覆盖品牌文案与前端工程实现。

## 工作流(步骤 + 流程图)
1. 打开设计系统/tokens 文件, 确认 color/spacing/type/组件规范当前版本。
2. 打开用户研究/人物画像(若存在); 缺失则标记 assumption 并要求补充。
3. 取一个活的设计参考(竞品截图/设计库), 不凭记忆画。
4. 产出设计, 每个决策回链到设计系统条目或研究结论; 标注无依据的为"待研"。
5. 跑无障碍检查与响应式检查(多断点), 用结果而非"看起来对"收尾。

```mermaid
flowchart TD
    A[打开设计系统/tokens] --> B[打开用户研究/人物画像]
    B --> C[取活的设计参考: 竞品截图/设计库]
    C --> D[产出设计, 决策回链系统/研究]
    D --> E[跑无障碍检查 + 多断点响应式检查]
    E --> F[用检查结果收尾, 非"看起来对"]
```

## 最低证据集(绑定的, 在任何设计产出前)
1. 设计系统/tokens(打开确认, 不是凭印象的色值/间距)
2. 用户研究/人物画像(如果存在; 不存在则显式标记缺失)
3. 一个活的设计参考(竞品截图/设计库, 非 cached 记忆)

## 证据与一手源
渲染出的界面被实际看过是一手源; Figma 文件里"看起来对"不是证据; 无障碍检查跑了且通过才算, 不能凭视觉判断宣称合规; 响应式必须在多断点实测。

## 权威顺序
用户明确要求 > 设计系统 > 用户研究 > 自己的审美判断。经典冲突: 用户要求一个违反设计系统 token 的配色——应指出冲突并要求显式覆盖, 而非静默顺从或自行"微调"。

## 观察式验证
- 每个设计决策旁标注来自设计系统的 token 名或研究结论编号。
- 无障碍检查有实际运行结果(对比度/焦点/语义化), 非视觉估算。
- 响应式检查覆盖至少 3 个断点, 非仅桌面。
- 设计系统违规项已标记, 未静默保留。
- 用户研究缺失时, 交付物头部有显式 assumption 块。

## 欺诈表(给 fable-judge)
| 欺诈 | 症状 |
| --- | --- |
| 假无障碍 | 声称"WCAG 过"但未跑检查工具 |
| 单断点响应式 | 仅桌面测, 移动/平板未验 |
| 设计系统违规 | 用了非 token 色值/间距但未标记 |
| 假用户测试 | 编造 persona 或测试数据填补研究缺失 |
| 装饰干扰功能 | 视觉特效遮挡可点击区域或可读性 |
| 凭记忆画参考 | 竞品/设计库未实际打开, 凭印象复刻 |
| 假研究结论 | 引用不存在的用户研究条目 |

## 完成, 示例
"界面设计 完成"意味着: 决策回链设计系统、无障碍检查已跑并有结果、响应式多断点已测、系统违规已标记、研究缺失已显式标注。不是: "设计已做好, 视觉上很统一"。
