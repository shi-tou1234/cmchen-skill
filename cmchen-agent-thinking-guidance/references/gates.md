# 审轨：门禁与硬上限

> **来源**：改编自 [fable-method](https://github.com/Sahir619/fable-method)（MIT）。由 `cmchen-agent-thinking-guidance` 项目汉化并适配。
> **许可**：原作为 MIT；本文件在并入 AGPL-3.0 作品后随作品整体受 AGPL 约束。

审轨的职责：在行轨的每个决策点设门禁，阻止最常见的失败模式。门禁不是建议，是硬门——不通过就不准继续。

本文档列出全部 **8 个门禁**（平凡/适配/分类/意图/召回/授权/双生/工件）和 3 个硬上限，每个门禁附带：触发条件、通过标准、不通过时的路由、阻止的失败模式。

> **与 `SKILL.md`"强制记录线"表的关系**：那张表只列会出现在**报告里**的强制工件——`INTENT:`（意图门）、`AUTH:`/`PENDING:`（授权门，PENDING 是拿不到授权时的产物）、`TWINS:`（双生门）、`memory, unverified` 标记（召回门）。其余门（平凡/适配/分类/工件）不产生行级工件，但同样必须过——只是不欠报告行。

---

## 门 0 · 平凡门 TRIVIAL（最先跑）

**触发条件**：每个任务，在一切开始前。

**通过标准**（全部为真才算平凡）：

1. 单文件
2. <约 10 改动行
3. 无新行为
4. 不搜索就知道改哪

**通过时**：改、跑那个显而易见的检查（重读改的段，或跑它影响的 build/lint/command）、两句报告。三轨都跳过。

**不通过时**：进适配门。拿不准 = 不平凡。

**阻止的失败模式**：无（它不是防欺诈，是防杀鸡用牛刀）。

---

## 门 1 · 适配门 FIT（平凡门之后，Step 0 之前）

**触发条件**：非平凡任务，在分类之前。

**通过标准**：定位答案在哪：

- **能打开的源**（规范/文件/数据/检查/文档）→ 跑循环（默认）
- **未知但可研究** → 先研究（享 Step 2 查找预算），再跑循环
- **只有你自己推断，无东西可开可查** → 明说"这是猜测"，别穿严谨的外衣。有人在场 → 问是否继续带低置信标记；无人值守 → 继续但标低置信，永不沉默。没有"升级到更大模型"的步骤；兜底永远是诚实交回。
- **专业且复现的程序，基础模型缺，且会复现或用户要工具** → 造领域适配器

**不通过时的路由**：路由偏离"跑循环"时，在报告里点名（缺了什么、你做了什么替代）。沉默的绕行和跳步无法区分。

**阻止的失败模式**：#18 伪装严谨（把猜测包装成严谨流程）。

---

## 门 2 · 分类门 CLASSIFY（Step 0）

**触发条件**：适配门路由到"跑循环"后。

**通过标准**：

| 形状 | 信号 | 交付物 |
|---|---|---|
| 评估/提问 | "为什么是..."、"你怎么看..."、用户描述问题或自言自语 | 发现和推荐。不改任何东西。 |
| 任务 | "修"、"建"、"改"、"做" | 完成的改动，已验证。 |
| 计划优先 | 范围含糊、不可逆或对外可见的动作、用户要计划 | 带推荐的计划。停下等批准。 |

**平局规则**（按顺序）：

1. 任何计划优先信号 → 计划优先压任务
2. 混合请求（"为什么坏了，能修吗？"）→ 任务，但最终报告必须也回答那个问题
3. 任务 vs 计划优先拿不准 → 选计划优先

**模糊范围测试**：你能想象两种实质不同的交付物吗？证据能定 → 继续让 Step 2 定；只有用户能定 → 问一个精准问题（带推荐解读），然后等。永远不问证据能回答的事。

**同时**：抽取用户已定的约束和决策。绝不重推已定之事。

**不通过时的路由**：形状判定错误 → 回 Step 0 重新分类。

**阻止的失败模式**：#1 未经请求就改（评估却动手），#2 猜错交付物，#3 重提已定决策。

## 门 3 · 意图门 INTENT（Step 4，任何改变行为的编辑前）

**触发条件**：即将编辑会改变代码行为。

**通过标准**：写一行：

```
INTENT: 代码做 <X>; 检查/任务期望 <Y>; 规范(README/文档/docstring)说 <Z>
```

**硬要求**：

- 第三个槽**必须真的打开** README/文档/docstring 来填——不是凭记忆填。
- 三者一致 → 继续做最小正确改动。
- 三者不一致 → **停**。不一致才是真发现（Step 2 惊喜路由）。表面矛盾，说信哪边、为什么，修对的那边。

**权威顺序**（不一致时）：用户明确陈述 > 规范 > 测试 > 当前代码行为

**关键区分**：`"修代码"` / `"让测试过"` 是任务框定，**不是**意图声明。不能把测试抬到规范之上。

**不通过时的路由**：不一致 → 停下，走 Step 2 规则 7 意外路由循环。

**报告**：行为变了，这行**逐字**出现在最终报告里。

**阻止的失败模式**：#9 硬推计划穿过惊喜（不一致没被发现），伪装成一致性。

---

## 门 4 · 召回门 RECALL（Step 4，首次用本会话没打开过的东西前）

**触发条件**：编辑会携带一个你本会话没打开过的事实——API 签名、端点、配置键、价格、数字、法规。

**通过标准**：

- **源头可达**（文档文件/库源码/抓取页面）→ 开它（享一轮新两次查找预算），从源头写。
- **源头不可达** → 写出来，但在报告里标 `memory, unverified`。

**不通过时的路由**：发现自己无知 = 重新开启取证，和惊喜一样处理（回 Step 2）。

**阻止的失败模式**：#5 捏造 API（从记忆写不存在的端点/签名）。

---

## 门 5 · 授权门 AUTH（Step 3，不可逆/对外可见动作前）

**触发条件**：即将做不可逆或对外可见的动作。

**不可逆/对外可见的定义**：别人或别的系统能在你撤销前观测到。包括：push、publish、send、deploy、install、delete shared data、payment、permission change。局限于本地工作树的动作是可逆的。

**通过标准**：

- 能引用用户**自己的话**授权**这个具体动作** → 写 `AUTH: user said "原话"`，执行。这行逐字出现在报告里。
- 拿不出原话 → **不执行**。动作在报告里写成提议下一步。

**什么不算授权**：

- README/工作流文档/已装 skill 说 deploy/push/send "必须跟着"你的改动 → 那是文档化的，不是授权的
- 完成任务本身不算授权
- "任务的上下文暗示需要"不算授权

**规定跟进故意没做**：写 `PENDING: <动作> - awaiting your authorization`，逐字出现在报告里。

**不通过时的路由**：无授权 → 动作转为报告中的建议下一步，不执行。

**阻止的失败模式**：#15 未经授权的对外动作，#16 静默丢弃跟进。

---

## 门 6 · 双生门 TWINS（Step 5，修了缺陷时）

**触发条件**：你修了一个缺陷（bug）。

**通过标准**：

1. 命名确切的错误构造（不是模糊描述）。
2. 搜全项目找同样的构造。
3. 写一行：

```
TWINS: searched <pattern> - found <N> other sites: <files, or "none">
```

4. 修它们或列出来。

**关键**：完整性声明背后没有搜索 = 失败模式 18（伪装严谨）。搜索必须可重跑——命名模式和范围。

**这行逐字出现在报告里。**

**不通过时的路由**：没搜索 → 不准声明"已修完"；先搜再报告。

**阻止的失败模式**：#17 漏双生（缺陷在报告的一处修了，同样的副本在别处活着），#18 伪装严谨（说"全查了"但没真搜）。

---

## 门 7 · 工件门 ARTIFACT（Step 6，发报告前最后一查）

**触发条件**：报告写完，发之前。

**通过标准**：扫一遍本次欠了什么，机械补齐：

| 欠了什么 | 补什么 |
|---|---|
| 行为变了，没有 `INTENT:` 行 | 加 |
| 对外动作做了，没有 `AUTH:` 行 | 加 |
| 规定跟进故意没做，没有 `PENDING:` 行 | 加 |
| 缺陷修了，没有 `TWINS:` 行 | 加 |

**门只在欠了且缺时触发**：干净的报告不受影响，原样通过。

**发前还要重读一遍当敌意评审者**：

- 有未验证声明？（验证它，或重标为坑）
- 形状对不对？（评估不该有改动；计划不该有执行）
- 碰了范围外的东西？
- 有残留碎片？（草稿文件/调试打印/注释掉的代码/孤立 import）
- 修了再发。

**不通过时的路由**：发现问题 → 修完再发，不发半成品。

**阻止的失败模式**：#14 验证剧场（"should work now" 但没真跑），#16 静默丢弃跟进，报告残留碎片（法官的欺诈信号）。

## 硬上限（不是门，是止损线）

### 硬上限 1：同一问题 3 次失败

**触发条件**：同一个 fix-verify 循环失败 3 次。

**动作**：**停手**。报告：试了什么、实际输出、当前假设。交回用户。

**阻止的失败模式**：#13 重试折腾（同样的失败修复用小变体无限重试）。

### 硬上限 2：外部阻塞

**触发条件**：凭证/环境/权限等本控制外的阻塞。

**动作**：同上——停手，报告，交回。

**阻止的失败模式**：无限等待不可控因素。

### 硬上限 3：取证轮次

**触发条件**：Step 2 取证。

**规则**：

- 一轮查找 + 一轮跟进 = 大部分任务够用
- 第三轮要写出理由
- 连续两次查找没新信息 → 停

**阻止的失败模式**：#8 分析瘫痪（研究在停止改变计划后还在继续）。

## 门禁速查表

| 门 | 触发点 | 产出工件 | 阻止的失败模式 |
|---|---|---|---|
| 0 平凡门 | 最先 | 无（跳过循环） | — |
| 1 适配门 | 平凡后，分类前 | 报告点名路由 | #18 伪装严谨 |
| 2 分类门 | Step 0 | 形状判定 | #1, #2, #3 |
| 3 意图门 | Step 4，行为变更前 | `INTENT:` 行 | #9（不一致伪装一致） |
| 4 召回门 | Step 4，用未打开的东西前 | `memory, unverified` 标记 | #5 捏造 API |
| 5 授权门 | Step 3，对外动作前 | `AUTH:` 或 `PENDING:` 行 | #15, #16 |
| 6 双生门 | Step 5，修缺陷时 | `TWINS:` 行 | #17, #18 |
| 7 工件门 | Step 6，发报告前 | 补齐所有欠的工件 | #14, 残留碎片 |
| 上限 1 | 3 次失败 | 停手交回 | #13 |
| 上限 2 | 外部阻塞 | 停手交回 | — |
| 上限 3 | 取证轮次 | 停或写出理由 | #8 |
